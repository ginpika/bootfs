# 自治节点与动态组网

节点、组网与副本的概念及设计取舍见[去中心化设计](decentralization-zh-CN.md)（[English](decentralization.md)）；本文提供配对、退出与协议操作说明。

BootFS 的每个新节点都是完整的独立文件服务：整文件、权威元数据和本地索引都在本机。加入集群只建立成员目录、联合查询和请求转发关系，不合并其他节点的文件元数据库，不改写资源 UUID，不把本机读写放进全局 Raft。

## 启动

```sh
java -jar target/bootfs-v1.0.0-beta.1.jar \
  --spring.profiles.active=dev \
  --tfs.root-path=/absolute/path/to/node-a \
  --tfs.web-entrypoint=http://127.0.0.1:8181
```

默认 `bootfs.metadata.mode=auto`。新目录和已有本地 embedded RocksDB 目录使用同一套本机权威存储；已有本地数据无需导出、移动或清空即可启用组网。`dynamic`、`embedded` 显式配置也使用本地内核。新组网只需要 HTTP 入口，不需要 Raft 端口或 `bootfs.raft.allow-insecure-network`。跨机器请配置对等节点能访问的真实 HTTP/HTTPS 地址；生产使用 HTTPS 或受保护的私网/隧道。

同机启动第二个节点时使用另一个根目录，设置 `--server.port=8182` 和 `--tfs.web-entrypoint=http://127.0.0.1:8182`。节点 ID 和 HTTP 入口持久绑定本机存储，不能复制同一份身份目录冒充两台节点。

第一代全局 Raft 的旧 `kernel/dynamic/node.json` 或静态 Raft 数据不应直接解释为本地库。静态 Raft 仍保留兼容运行路径，旧动态 Raft 目录需用 [离线备份恢复](mononode-backup.md) 还原到新本地 seed；原数据和日志保留。未完成、缺失身份或多种权威状态冲突的目录会拒绝自动接管。

## 验证码连接

1. 在目标节点打开 `/dashboard`，点击“连接 BootFS 节点”→“生成本机验证码”。
2. 在发起节点填写目标 HTTP URL 和 8 位验证码，点击“连接”。
3. 页面确认双方处于同一组网，且成员目录包含彼此后显示成功。资源不会被搬迁或导入对方数据库。

验证码有效 5 分钟，连续输错 5 次失效，一次授权不能用于另一台节点。同一请求可在有效期内恢复丢失的响应。更换所属集群后，旧验证码失效。页面不会保存验证码或通信凭据。

可以从独立节点或已有组网的任一成员发起连接；已有成员会把加入请求转交给当前成员协调节点。两个各有多个成员的组网不会自动合并，需要先退出其中一个，再加入目标。

节点身份、签名密钥及逐节点传输授权由程序生成、交换和持久保存，无需手工配置。验证码兑换不会导出本机管理凭据。成员请求附带签名、时间和随机值，JSON 命令绑定实际请求体；知道旧传输授权也不能冒充另一台节点。首次验证码交换仍应使用可信的地址和传输通道。

生成验证码、连接和退出统一在系统仪表盘的“连接 BootFS 节点”对话框中操作。当前新内核采用显式 URL 配对，原有 Raft/组播自动合并流程不参与组网。

## 独立 → A → 独立 → B

“退出当前集群”执行本机持久退群，不停止文件服务。退出后的行为是：

- 本机文件、UUID、完整元数据和本地索引保持不变，可以继续读写和搜索。
- 本机建立新的独立组网身份，并立即移除原组成员的本机访问授权。
- 对原组的成员更新进入持久通知队列；对端离线时重试，不阻止本机读写或加入 B。
- 重启保持独立，不自动返回 A。之后可以用 B 的验证码加入 B，无“曾经入群就不能再入群”的限制。

原组的在线节点收到退群通知后撤销该节点授权、移除其远端查询入口。离线节点获知退出存在传播延迟。退出时不删除任何节点持有的完整副本；原组若没有完整副本，就不能继续读取已离开节点的文件。

协调节点只负责串行维护成员目录，不存放其他节点的文件权威。正常退出协调节点时，目录职责移交给剩余 nodeId 最小的节点。协调节点突然不可达时，新增成员暂时需要等待它恢复；现有节点的本机读写、联合查询可达部分以及本地退出均继续工作。不会因为联系失败自动更改数据权威或把网络分区变成新文件历史。

## 查询、修改和 S3

- 本地 Lucene 只索引本机持有的资源；索引可以从本机元数据重建。
- `/queryPageOffset` 和全文标签查询临时向成员查询，结果不写入本机权威库或 Lucene。
- 目录浏览从各成员读取本机对象键并合并同路径文件夹。文件的显示名可以独立于目录路径修改。
- 联合分页按 nodeId 分组，再使用节点本地排序；不承诺跨节点同一时刻的快照或统一相关性排名。
- 不可达节点通过 `partial`、`unavailableNodes` 返回，并在资源列表提示。未知远端资源无法确认不存在时返回暂不可用，不伪造删除或修改成功。
- 重命名、标签、公开状态和删除请求发给持有文件的节点；远端不可用时不在本机代写远端元数据。
- 网格视图可将文件拖入任一可达成员的目录。文件所属节点更新逻辑路径，文件内容留在原节点。跨节点批量移动按所属节点分别提交并返回各节点的失败情况。集群成员需升级后才能通过新的目录接口互相浏览和移动文件。
- `meta:local` 只查询本机资源，不等待其他节点。
- S3 的 bucket/key 属于接收请求的节点。组网不自动合并 S3 命名空间，也不承诺跨节点 key 唯一或跨节点事务。
- 资源地址由持有节点 URL 和 UUID 确定。相同 UUID 出现在多个节点时，使用具体持有节点 URL；不为组网重写本机 UUID。

## 完整副本

`single-local` 为默认发布策略，本机落盘即可发布；设置页的副本份数 可要求后台制作完整副本。`replicated(k)` 发布前仍需 k 个不同节点确认完整字节及准备元数据的耐久保存；显式选择该策略后，副本不足仍会等待或返回待完成，不会因退群自动降低已开始上传的策略。

新复制协议传输整文件与元数据快照，接收端先验证长度、SHA-256 并保存准备记录，源节点发布后显式确认副本发布。确认意图由源节点持久重试。接收节点保存自己的文件清单、资源路由和完整检索源文档，并保留原始来源、作者、描述及 S3 绑定快照，独立读取不需要源节点在线。

副本拥有本机 UUID，并以 `copyOf` 记录来源，不会在本机冒充源对象的权威。原 S3 绑定保留在来源快照中，不自动覆盖本节点 S3 key。缩略图、HLS 和相册派生物未作为跨节点原始文件分块传输，副本的派生物可从完整原始文件重新生成。

同组且源节点可达时，后台跟随源节点的元数据和删除记录；源节点不可达时保留最后一份完整快照。退出后不再接受原组同步。在本机编辑副本的名称、标签或公开状态，会先持久标记为独立分支，后续源元数据不覆盖这些本机修改。节点之间不做任意多主历史自动合并。

## 存储与备份

- `data/`：本机完整对象和媒体派生物。
- `uuid`：稳定的物理存储节点身份。新节点默认生成 16 位字母数字 ID，已有节点从磁盘读取原 ID。
- `kernel/metadata/`：本机权威 KV，包括清单、源文档、S3 key、删除状态、副本快照。
- `kernel/search/`：本机可重建索引。
- `kernel/cluster/node.json`：成员目录、逐节点授权、成员变更通知队列；不包含文件数据库。
- `kernel/security/cluster.json`：自动管理的节点身份和本机管理凭据。

后两个文件仅文件所有者可读写。完整根目录备份应保留它们；逻辑备份恢复会创建新的组网身份。每个自治节点可独立离线备份，不需要取得其他成员的数据库或保持相同 revision。多节点整组导出目前只保留对旧共享 Raft 数据的兼容工具，新组网应逐节点备份。

## 管理 API

生成验证码和发起连接需要本节点登录会话（明确关闭 SSO 的可信环境除外）：

```text
POST /api/cluster/pairing/code
POST /api/cluster/link             {"url":"http://target:8181","code":"12345678"}
GET  /api/cluster/link/status?url=http://target:8181
GET  /api/cluster/status
POST /api/cluster/leave
POST /api/cluster/remove           {"nodeId":"..."}
```

`/join`、`/membership`、`/departure`、`/connect`、`/data/*` 为签名对等节点协议。它们不用于导入其他节点的整个文件元数据库。旧 `/merge`、`/admit` 以及共享 token 换群流程不再参与新组网。
