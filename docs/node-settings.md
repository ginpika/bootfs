# 节点设置与升级

打开首页右上角「设置」（`/settings`）。18 项业务设置以当前节点的 `kernel/settings` RocksDB 为唯一持久化来源；访问 A 修改 A，不经资源 KV、搜索索引、节点联合目录或配对协议复制到 B。

新安装默认不启用 SSO、不限角色、允许本机直连、允许公开读取及内网延迟检测；S3 默认关闭且没有凭证。启用 SSO 后设置页继承认证与角色规则。关闭 SSO 时共享管理功能也不校验用户身份，所有模式仍保留来源检查、正文限制、SigV4 和节点签名边界。角色留空明确表示所有已认证角色均可访问共享应用，并不建立用户数据隔离。

| 分组 | 设置与新安装默认值 | 生效范围 |
|---|---|---|
| 访问权限 | 公开读取开启；内网检测开启 | 保存后读取 / 新检测任务 |
| 登录认证 | SSO 关闭；角色不限；本机访问开启；认证地址、用户中心链接留空 | 保存后请求；客户端随服务地址更新 |
| S3 | 服务关闭；访问密钥、秘密密钥未设置；桶 `bootfs` | 新请求；桶变更受控重启 |
| 存储 | 副本 1（含本机）；策略 `single-local`；同步份数 0（沿用副本数）；超时 30000ms | 新上传任务，已开始任务保留原份数和超时 |
| 节点 | 地址 `http://localhost:8181`；代理策略 `none`；可信代理仅回环 | 地址受控重启；代理重启 |

`replicated` 策略至少需要 2 份。设置页先完整验证，单条数据库事务同步持久化，再发布不可变配置快照；保存失败保持原设置。版本号防止不同页面互相覆盖。输入秘密密钥留空保留已有值，勾选清除才删除；服务开启时不允许清空凭证。生成凭证使用浏览器安全随机数，保存后两项凭证都只显示配置状态，不回显原值。

## 首次升级与优先级

仅在该节点设置库首次初始化时导入明确提供的旧 18 项环境变量（或对应 Spring 属性）。旧 `BOOTFS_CLUSTER_TOKEN` 仅供缺少持久凭证时的一次兼容导入；已有 `kernel/security/cluster.json` 始终优先，移除环境变量不会重新生成身份。旧节点入口以 `kernel/cluster/node.json` 中的身份为准，避免遗留启动值造成失联。已入库的值不会在后续启动被环境变量、命令行或 Compose 默认值覆盖。Compose 已移除这些普通配置注入，新安装不需要填写它们。导入的旧 S3 配置若缺少完整凭证，保持服务关闭并在设置页提示，不阻止应用启动。

如果升级时只保留了旧 `.env`，Compose 不会自动把其中普通设置注入容器。需要保留旧值时，在第一次启动新版本前，临时用 Compose override 的 `env_file` 或显式 `environment` 传入这些旧项；初始化完成后移除临时注入。直接 Java 启动也不会自动读取 `.env`。不要删除设置库来恢复默认，密钥和节点身份须作为同一节点安全状态保留。

`BOOTFS_METADATA_MODE` 仍是可选启动参数，默认 `auto`；它决定如何打开元数据，不出现在普通设置表单。根目录、端口、FFmpeg 等不属于本次迁移范围。

## SSO 测试与避免失去访问

先填写认证服务地址并点击测试连接。服务需提供可解析的 `/api/sso/session` 响应，测试超时或返回错误则拒绝应用。开启认证或更换认证地址、角色、本机访问规则时，保存操作会再次测试，要求当前 Cookie 能通过目标认证服务及新角色规则，或者操作者确实从原始回环连接访问且保留本机访问。单纯能连接到服务器不等于当前用户已获授权。

本机访问始终使用 Tomcat 在解析转发头前采集的原始连接、Host、代理标记及浏览器来源。Docker 网关、内网地址、带转发标记的代理流量均不是本机；详见 [本机访问](local-access.md)。

## 节点地址与桶名的受控变更

1. 节点地址：先离开集群，完成成员通知和所有配对、上传、复制任务。填写可被其他节点访问的新地址并勾选确认。当前进程继续使用旧地址。
2. 桶名：先保存关闭 S3，完成所有上传、复制任务，再填写新桶名并确认。当前进程继续使用旧桶；待迁移时不允许开启 S3。普通上传在停机前产生的绑定也会在重启时迁移。
3. 保存后重启当前节点。在元数据和节点服务启动前，程序取得资源库独占锁，重新检查条件，原子迁移桶绑定；节点地址同时更新身份文件、自身成员地址、资源路由和预览链接。节点 ID、签名身份和数据字节保持不变。
4. 条件变化或目标桶存在不同绑定时，检查阶段取消变更，保留原配置，设置页显示原因。中途 I/O 故障保留恢复日志并停止启动，下一次启动重试，避免以不一致身份运行。不要删除恢复日志或原始安全文件。
5. 成功后从新入口访问，重新配对节点；桶变更完成后再开启 S3。无需配对其他节点的代理或凭证配置。

恢复原地址 / 桶名并保存可取消尚未执行的变更。现存静态/旧共享 Raft 存储的地址及桶迁移需先通过便携备份恢复到本地节点。已失去网络连接的旧公开 URL 不会变成自动转发别名；如需旧链接连续可用，应在旧入口保留转发。

## 反向代理

设置页保存代理策略及可信来源正则后，下一次启动会在 Tomcat 和转发过滤器初始化前从数据库读取。默认 `none`，可信来源仅回环。Caddy/Docker 示例见 [仪表盘](dashboard.md)。`native` 仅信任匹配的连接来源；`framework` 本身不按此 Tomcat 正则筛选，必须在边缘清理转发头并限制后端直连。

## 凭证与备份恢复

秘密密钥及完整配置记录由 AES-GCM 加密后存入设置数据库，保护密钥自动保存在本机 `kernel/security/settings.key`（0600），不增加环境变量。节点管理 token 与 Ed25519 私钥仍在 `kernel/security/cluster.json`。设置 JSON、原始 KV、联合节点响应和常规日志不返回这些秘密。设置页只允许轮换管理 token，不显示它；轮换保留签名身份、已配对节点能力，旧 token 及未用完的配对验证码失效。

- 同节点灾难恢复：停机后安全备份整个数据根目录，必须将 `kernel/settings`、`kernel/security/settings.key`、`kernel/security/cluster.json` 和 `kernel/cluster` 与数据、元数据一起保留。包含安全文件的完整备份应受访问控制。缺失已初始化配置的保护密钥会拒绝启动，不能自动重新生成。
- 便携备份：`KernelBackup` 在校验和保护的 manifest 中按节点保存可迁移设置，排除入口地址、代理配置、S3 凭证、节点凭证和待执行变更；有待变更时拒绝导出。不会把配置加密密钥放进便携包。
- 便携恢复：恢复为同名节点时选择其可迁移设置；只有一个来源时也可移植到新节点。多个来源且没有同名节点时使用新安装默认，需在页面手动选择配置，避免悄悄覆盖节点特有状态。恢复的 SSO/S3 默认关闭，重新配置凭证后开启。新入口来自恢复命令，旧入口与代理不会覆盖它。

公开开关迁移的是已有读取总开关，不是完整 S3 ACL 或 Bucket Policy。跨节点 JSON、缩略图、普通预览仍使用配对 token 和签名，不转发用户 Cookie；下载 `/f`、HLS、Clash 转换订阅既有的 302 路径仍存在，本次未将它们改成全程代理。
